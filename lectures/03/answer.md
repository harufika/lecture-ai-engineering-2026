    ```
    3. **レベル3（発展・応用・プロ級）**
      * **対象:** 経験者、またはより深く学びたい意欲的な人。
      * **内容:** ゼロからコードを設計する、応用的なアルゴリズムを実装する、オープンエンドな課題（正解が一つではない難易度の高い課題）。

    * 宿題が出された回のテーマ
    ```

#### 3.2 プログラムの書き方の比較

| 比較項目 | 標準版（Pydantic AI） | ADK版 |
|---|---|---|
| エージェントの定義 | `Agent(instructions=INSTRUCTIONS, ...)` | `root_agent = Agent(name=..., model=MODEL, instruction=INSTRUCTIONS, tools=[...])` |
| 指示を渡す引数 | `instructions` | `instruction` |
| ツールの登録 | `agent.tool_plain(...)` で登録する | `tools=[...]` に関数を渡す |
| モデルの指定 | `run_sync` 実行時に渡す | エージェント定義の `model` に渡す |
| 質問の入力・回答表示 | 自分の `main()` で引数を受け取り、実行・表示する | `adk run` の対話機能を使う |
| LLMとツールをつなぐ内部ループ | Pydantic AIが担当 | ADKが担当 |
| 実行情報の確認 | 自作の `--trace` | ADKの `--jsonl` |

- **ADK版は、共通の設定と関数を読み込み、`root_agent` を定義し、adk runを通じて対話を実行した。** 

#### 3.3 実行方法・確認方法

標準版では、質問をコマンドの引数として渡した。他の2問も同じ形式で実行した。

```bash
uv run python -m app.agent --trace "LoRAとQLoRAの違いは？"
```

ADK版では次のコマンドで起動し、`[user]:` に同じ質問を入力した。

```bash
PYTHONPATH=. uv run --with google-adk adk run --jsonl adk_agent/glossary_agent
```

| 確認対象 | 標準版 | ADK版 |
|---|---|---|
| ツール名・引数 | `[tool call]` | `functionCall` の `name`・`args` |
| ツール実行回数 | `tool_calls` | `functionCall` の個数 |
| LLM呼び出し回数 | `requests` | モデル応答イベントの数 |
| ツールの戻り値 | `[tool return]` | `functionResponse` |

ADKのJSONLは各質問で3イベントあったが、そのうち1イベントはツールの戻り値なので、LLM呼び出しは2回と数えた。

### 5. 気づき・疑問

- **事前の予測と結果**：同じモデル・指示・演習用ツール・質問なら、Agentが変わったとしても回答も同じになるのではないかと考えた。今回の検証では、文章は完全一致しなかったが、3問とも回答内容の概要とツールの使い方は一致した。
- **コードの書き方**：ADKではエージェントを定義し、対話入力・回答表示を `adk run` に任せられた。共通の設定や関数も再利用できるため、新たに書くコードを短くできた。
- **ライブラリの役割**：標準版とADK版の差について、ADKでは対話実行の仕組みもライブラリ側の機能を使うことができると分かった。
- **ログで分かったこと**：回答の文章だけでなく、traceやJSONLを見ることで、使ったツール・引数・回数を根拠として比較することができた。ツールの実行回数とLLMの呼び出し回数についても、細かく確認することができた。
- **処理時間**：ADK版の最初の手動実行では最初のAPI応答まで1分程度の時間を要したが、その後の2問は短い待ち時間で回答された。
- **今後の疑問**：今回の検証では単純な質問だったが、より複雑・長文な質問を行う場合、ログを参照しながら実行する場合、複数のツールを場合分けして使うような場合で、同じような傾向があるのか疑問に感じた。
