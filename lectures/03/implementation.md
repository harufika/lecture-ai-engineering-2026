# 第3回 実装結果：承認付き学習記録の保存

### やったこと

- `app/tools.py` に `save_learning_log(content: str) -> str` を追加した。学習記録をプロジェクト直下の `learning_log/` にMarkdown形式で保存する。
- 記録ごとに異なるファイル名を作り、既存の記録を上書きしないようにした。空白や改行だけの内容は保存しない。
- `app/agent.py` で `requires_approval=True` を付けて登録し、`output_type=[str, DeferredToolRequests]` を指定した。
- CLIでは、承認待ちの結果を受け取ったら保存する本文を表示し、`y` の場合だけ保存を許可するようにした。承認・拒否の結果は `DeferredToolResults` に入れ、それまでの会話履歴とともに渡して処理を再開する。

### 結果：3回の実行の比較

使用モデルは、すべて `gemini-3.5-flash-lite`。

| 実行 | 依頼文 | INSTRUCTIONS | 保存ツールの呼び出し | 結果 |
|---|---|---|---|---|
| 1回目 | 通常の保存依頼 | 保存ツールを使う指示の追加前 | なし | AIの文章による確認で終了。CLIの保存確認には進まず、保存されなかった |
| 2回目 | ツール名と承認方法を明示 | 1回目と同じ | あり | CLIで確認が表示され、`y` を入力して保存できた |
| 3回目 | 1回目と同じ依頼文 | 保存ツールを使う指示の追加後 | あり | CLIで確認が表示され、`y` を入力して保存できた |

#### 1回目：実装後、通常の言葉で保存を依頼した

```bash
uv run python -m app.agent --trace "LoRAとQLoRAの違いは？違いを説明した学習記録を 作り、保存してください。"
```

保存関数・承認付き登録・CLIの確認処理は実装済みだったが、モデルは文章で「保存をご希望の場合は」「よろしければお知らせください」と返し、そのまま終了した。

traceにあったのは、`search_glossary` によるLoRAとQLoRAの検索だけだった。`save_learning_log` は呼ばれておらず、実装した「この内容を保存しますか？ [y/N]:」も表示されなかった。

これは保存が拒否されたり、プログラムがエラーになったりしたのではなく、モデルが保存ツールを選ばなかったため、承認処理に到達しなかったという結果だった。

#### 2回目：プログラムを変えず、依頼文を詳しくした

```bash
uv run python -m app.agent --trace "LoRAとQLoRAの違いを調べてください。その違いをまとめた本文を引数にして、save_learning_log ツールを読んでください。保存の承認はターミナルからユーザが行います。"
```

1回目からプログラムもINSTRUCTIONSも変更せず、利用者の依頼文に関数名・渡す内容・承認方法を明示した。実行時の表記は「読んでください」だったが、モデルはツールを呼び出す依頼として扱った。

今回は保存する本文とCLIの確認が表示され、`y` を入力した後に保存された。traceでも `save_learning_log` の呼び出しと、次の保存先を返す実行結果を確認できた。

```text
learning_log/5bc3ae0acadf46a89b0ac1b51554ad55.md
```

**同じプログラムでも、利用者の聞き方を変えることで、モデルが選ぶツールと、その後の処理の流れが変わることを確認できた。**

#### 3回目：INSTRUCTIONSを更新し、1回目と同じ依頼文で実行した

保存関数やCLIの承認処理はそのままに、`INSTRUCTIONS` に次の2行を追加した。

```text
- 学習記録の保存を依頼されたら、保存する本文を content に入れて save_learning_log を使う。
- 保存の確認はCLIが行うため、文章で事前確認せず保存ツールを呼ぶ。保存が拒否されたら、利用者から再依頼があるまで呼び直さない。
```

その後、1回目と同じコマンドを実行した。

```bash
uv run python -m app.agent --trace "LoRAとQLoRAの違いは？違いを説明した学習記録を 作り、保存してください。"
```

今度は保存する本文と「この内容を保存しますか？ [y/N]:」が表示された。`y` を入力すると保存され、traceでも `save_learning_log` の呼び出しと次の保存先を確認できた。

```text
learning_log/3978dc58098240d8869789414ced5343.md
```

**INSTRUCTIONSに使う場面を明示したことで、今回の実行では、利用者がツール名や承認方法を指定しなくても、元の依頼文で保存確認に進めた。**

### 動作確認

- `uv run pytest -q`：INSTRUCTIONS更新後も26件すべて成功。APIを呼ばないテストで、承認前には保存されないこと、承認時の保存、拒否・入力中断時の未保存を確認した。
- `uv run python -m app.agent --list-tools`：`save_learning_log` を含む4個のツールが表示された。
- 実際のLLMを使った手動確認：上記の3回を比較し、2回目と3回目ではCLIで承認して保存できた。手動での拒否操作は、この記録では未確認。

### 気づき・疑問

- ツールの関数を実装して登録することと、モデルが適切な場面でそのツールを選ぶことは別の問題だった。
- 1回目と2回目の比較から、プログラムを変更しなくても、利用者の依頼文によってツールの選択や処理の流れが変わることが分かった。
- 1回目と3回目の比較から、エージェント共通の指示であるINSTRUCTIONSに使い方を明示すると、利用者が毎回詳しく指示する負担を減らせると分かった。
- AIが文章で「保存してよいか」と聞くことと、プログラムがツール実行前に承認を求めることは異なる。今回の実装では、実際の保存可否をCLIへの入力で決めている。
- traceを見ることで、最終回答の文章だけでは分からない「どのツールが呼ばれ、何を返したか」を確認できた。
- 今回はINSTRUCTIONS更新後の1回の実行で改善を確認した。繰り返し実行した場合や、別の言い方でも同様に動くかは、今後の確認事項としたい。
