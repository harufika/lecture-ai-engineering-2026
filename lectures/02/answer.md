## 宿題

- 取り組んだレベル：発展


-  変えた設定やデータ
    - `scripts/make_sft_dataset.py` を使用し、講座の用語集からQ&Aデータ116件を作成した。
    - 教材のFAQデータを用語集のQ&Aに置き換え、学習用104件・検証用12件に分割した。

- 評価方法
  
  本評価として、以下の3種類の質問を各5問、合計15問用意した。

  - ① 用語集にある用語を直接尋ねる質問

    **目的：** 学習した用語の定義を正しく説明できるかを確認する。

    | No. | 評価用の質問 |
    |---|---|
    | 1 | トークンとは何ですか？ |
    | 2 | ハルシネーションとは何ですか？ |
    | 3 | LoRAとは何ですか？ |
    | 4 | 学習率とは何ですか？ |
    | 5 | 過学習とは何ですか？ |

  - ② 同じ用語を言い換えて尋ねる質問

    **目的：** 聞き方が変わっても、適切な説明を返せるかを確認する。

    | No. | 評価用の質問 |
    |---|---|
    | 1 | LLMが文章を扱う際の「トークン」は、どのような単位ですか？ |
    | 2 | AIが事実と異なる内容をもっともらしく答える現象を説明してください。 |
    | 3 | LoRAでは、モデル全体を更新する代わりに何を学習するのですか？ |
    | 4 | 学習率は、モデルの学習中に何を調整する値ですか？ |
    | 5 | 学習データにはよく答えられるのに、新しいデータで性能が落ちる状態を説明してください。 |

  - ③ 用語集にない用語を尋ねる質問

    **目的：** 今回の学習データに含まれない用語への回答が、学習前後でどう変わるかを確認する。

    | No. | 評価用の質問 |
    |---|---|
    | 1 | RAGとは何ですか？ |
    | 2 | 埋め込みベクトルとは何ですか？ |
    | 3 | ベクトルデータベースとは何ですか？ |
    | 4 | 検索の適合率とは何ですか？ |
    | 5 | 検索の再現率とは何ですか？ |

    ※「用語集にない」とは今回の学習用Q&Aに含まれないことを指し、基盤モデルが事前学習でその用語を学んでいないことを意味するものではない。

- 採点方法

  回答内容を、正解例と採点ポイントに基づいて評価した。
  採点基準は次のように設定した。

  | 点数 | 基準 |
  |---|---|
  | 2点 | 必要な内容を説明できており、重大な誤りがない |
  | 1点 | 正しい説明はあるが、必要な内容が不足している。重大な誤りはない |
  | 0点 | 重大な誤りがある、または回答できていない |

  確認を求めた回答も内容の得点は0点とした。
  用語集にない質問についても、説明内容が正しければ得点を与える方針とした。

  比較用の単純検索は、質問文に用語集の用語名が含まれるかを調べる方式とした。

  - 1件該当した場合：その用語の説明文を返す。
  - 該当しない場合：確認が必要と返す。
  - 複数該当した場合：確認が必要と返す。

  | 設定項目 | 値 |
  |---|---|
  | 基盤モデル | Qwen/Qwen3.5-0.8B |
  | エポック数 | 20 |
  | 学習率 | 0.0002 |
  | LoRAのランク（r） | 16 |
  | LoRAのalpha | 32 |
  | 学習時の最大系列長 | 512トークン |
  | 回答の最大生成長 | 256トークン |
  | seed | 42 |
  | 回答生成方法 | 貪欲生成（do_sample=False） |

- 補足実験

  本評価の結果を確認した後、複数の用語や関係を尋ねる3問を追加した。
  追加3問は本評価の得点に含めず、補足実験として扱った。

  | 質問の種類 | 質問例 |
  |---|---|
  | 用語集にある | 学習率とエポックは、それぞれ学習の何を調整するか |
  | 言い換え | 重みを一度にどれだけ変えるかという設定と、学習データを何周させるかという設定はどう違うか |
  | 用語集にない | 検索の適合率と再現率は、それぞれ何を測るか |

  - 学習後のモデルは、複数用語の関係や違いを十分に説明できず、不正確な内容も含まれていた。
  - 単純検索は3問とも確認を求めた。
  - 「学習率とエポック」の質問では両方の用語を見つけたが、複数該当の場合に回答しない設計のため、説明を返さなかった。
  - 用語名を含まない言い換えでは、対応する説明を検索できなかった。
  - これらは検索全般の限界ではなく、今回実装した単純検索の制約である。

- ファインチューニングが向く場面・向かない場面についての考察

  - 今回の学習では、学習データに近い質問に対し、用語集に沿った説明を返せるようになった。特定分野の説明内容や回答の書き方をそろえる用途では、ファインチューニングの効果が期待できると考える。
  - 一方、直接質問は学習データに近い表現であるため、この結果だけで幅広い質問を理解できるようになったとは判断できない。
  - 言い換えや複数用語の関係を尋ねる質問では誤りが残った。今回のデータと学習条件では、定義の再現に比べて応用的な回答が難しかったと考える。
  - 用語集にない知識を今回のQ&A学習だけで正確に補うことはできなかった。また、学習前より回答が悪化した例もあり、学習後の評価が必要である。
  - 単純検索はモデルの再学習が不要で、用語集を修正すれば回答内容も更新できる。定義をそのまま確認する用途では、管理しやすい方法である。
  - ただし、今回の単純検索は用語名の一致に依存するため、用語名を含まない質問や複数用語を比較する質問には対応できず、単純検索の検索方法に依存する部分が大きいと感じた。
  - 正確さが求められる用途では、得点だけでなく、誤った回答を断定した件数と、確認を求めた件数も分けて評価することが重要である。
